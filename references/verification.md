# 验证与返工

机器回答可测问题：文件可完整解码吗，帧数正确吗，时长和画幅对吗，同一时刻seek结果一致吗，缺字体或素材吗。框景检查覆盖关键文字、字幕区和动作落点；没有自动检测器就明确人工检查的时间窗，不宣称已全检。低分辨率的帧差指标看不见小区域的高频爬行：图片逐帧重绘造成的抖动，在 `om qa` 的数值上和正常运动混在一起（实测同一条卡片的两种画法，抖动与平滑的比值几乎相同）。这类只能在原始分辨率按 1× 播放看，不能用 qa 绿了代替。

亮度偏差要对参考量，不靠眼睛。把参考片和成片缩到同一尺寸，避开主体和文字，取背景区域比均值、中位数和 p95；暗场常见的偏差是整体亮了 2–3 倍。差值大时先查管线：是不是多做了一次线性↔sRGB 转换，或 canvas 在两种色彩空间之间来回绘制；不要先用压暗、暗角或调色去补。

独立审片人只拿原始需求、最终MP4、已确认的方向、节奏单（treatment.md）、上屏文字的出处表（每句字幕或界面文字对应哪张截图或哪页原文）和必须核实的事实；不先读制作者的解释。没有出处表，审片人会把官网原句误判成「自拟文案」。审片问题里必须有一条：「哪一段开始让人走神、哪里平了」——只问对错的审片抓不到「无聊」，而它是用户最常否掉的地方。报告写具体时间码、缺陷、严重程度、观看覆盖与限制，并绑定最终文件SHA。必须分辨：没讲明白、逻辑错误、字读不清、工艺粗糙、节奏单调或失控、无动机运镜、技术故障。按visual-direction.md分别检查静帧工艺与连续运动；指出哪处细节经不起靠近、哪段信息没有推进。

审片不以追逐一个高分为目标。修复阻断理解和使用的问题，验证原缺陷及相邻接缝。用户已接受的取舍无新证据不重开；用户明确要求停止时按要求收尾并陈述验证限制。

选定版本保存代码、时间轴、资产引用、声音及成片身份。返工从上一版实际交付出发，清点历轮补丁。导出后核对目标窗口发生了预期变化、其余窗口没有意外变化；编码差异与内容差异应分开处理。

只检查截图时不能声称审过运动；只跑音频指标时不能声称人耳听审；只跑spec转换时不能声称新题目成片验证通过。确认测试工具能检出故意破坏的输入，避免「全绿」来自检查根本没执行。

工程验收和作品验收分别记录。逐帧一致只证明修改边界或确定性，测试数量只说明这些反例被覆盖；二者不证明好看。明确遭用户否定的样片须降低为技术回归案例，并记下被否定的维度。改skill后至少由独立Agent在陌生题目上真实制作才构成迁移试用，作者在同一上下文里模拟两份答案无效。
